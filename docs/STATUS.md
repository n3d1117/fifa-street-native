### iOS/tvOS next

Measured: iOS and tvOS Simulator builds render the language screen. Unverified: real devices, controller input, gameplay, audio, saves, frame rate and thermals on device.

1. First device boot (A12 or newer): title screen, then the first match. Check memory headroom (jetsam) against the 1.5 GB bundle.
2. Verify NTSC game and present cadence during a real device match; confirm the PAL opt-in still paces at 50 Hz.
3. Pipeline prewarm: implemented with feature-only manifest sections for the M1 NTSC/PAL selectors and simulator capability profile. The worker prewarms matching selectors; missing draw pipelines compile synchronously. Apple2 Simulator reports different ROV/R32 feature bits than M1, so its matching section carries the 15 shared FIFA selectors and compiles them. Cold macOS Metal cache (cache deleted per run): shader library 340 ms, prewarm 1.5 s off the boot path; time to play 26.0 s async vs 28.2 s sync; 2-3 render-thread compiles (6 ms) remained. Mid-match dips to 30-37 FPS appeared in both cold arms (cold system caches), none warm; warm arms and the default match measured 60 FPS, 0 underruns. Needs device check: on a fresh iPhone/Apple TV install, `native.log` should show `[RRV_PCSX2_GS_PIPELINE_PREWARM] keys=250` (A13 feature bits are expected to match M1; unverified) and no first-match freezes. Metallib and `MTLBinaryArchive` work stays deferred until measured library or post-update stalls justify it.
4. On-device performance diagnostics (later): a periodic log line with the game-thread split (guest code, VU1, GS submit, present wait, idle), GPU ms per frame, pipeline compiles, thermal state and `os_proc_available_memory`, written to `native.log` while the app runs.
5. Apple GPU paths from ARMSX2 (each needs a switch and A/B): framebuffer-fetch ordering instead of barriers, iOS barrier rules. The Z-floor skip is moot (no depth quantisation in the pinned GS) and the other fixes are already upstream.
6. Parked: small settings overlay (video mode, scale, rumble) usable with a controller and TV-safe on tvOS; real app icon for macOS, iOS and tvOS (macOS uses the generated placeholder from `tools/package/make-icon.m`; tvOS needs layered images).
7. Real Xcode project (last): `application` targets that show the sources (not compiled by Xcode, whose clang 12 cannot build PCSX2 master or the runtime), a build phase that reads `PLATFORM_NAME` and runs the matching CMake build, and the assembled `.app` as the product, so Build compiles edits and Run launches in the iOS/tvOS Simulator and on macOS. Device installs stay on the IPA because Xcode 12.5.1 cannot deploy to current iOS. If this cannot be made to work, remove `project.yml` and `./rx xcode`.

### Embedded build efficiency

- Deferred: trimming libPCSX2 for the bridge. vixl, ccc, DEV9, DebugTools and USB are 43% of a clean bridge's summed `.ninja_log` action time, but they are not dead: the arm64 `GSDrawScanlineCodeGenerator` includes VIXL, core sources (`Elfheader.cpp`, `Interpreter.cpp`) include ccc/SymbolGuardian headers, and GS startup calls ImGuiManager/FullscreenUI. With per-platform ccache a warm bridge rebuild takes about 9 s, so only cold builds would gain. DEV9 and USB alone remain a possible cut.
