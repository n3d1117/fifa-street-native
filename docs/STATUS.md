The reachable FileIO semaphore pair and RPC packet trio execute their original guest code. The remaining direct TODO bindings have no direct static callers outside HLE-replaced bodies; indirect calls and later missions remain unverified.

EE coverage is regenerated by `./tz build`; the direct TODO binding count by `./tz where --unimplemented`.

The FP/VU0 correctness batch covers macro FMAC Z/S/U/O and FDIV I/D status, FPU root exception flags, VI0 write protection and bitwise CLIP bounds. Existing regressions cover root operands, CVT.W.S, quadword alignment, MMI lanes and VF0 protection. The technical roadmap's FP/MMI/VU0 audit item is complete at this regression scope; later-mission gameplay remains unverified.

B5 is complete: setup fetches pinned, checksum-verified ccache, and builds use it
when available. PCH timestamp suppression and content hashing allow unchanged
generated sources and headers to hit cache; CMake's sorted glob lists keep unity
membership stable. Cache location, size and bypass controls are documented in
README.md. T4's remaining build profiling, debug-info and linker trials stay open.

B2 is complete: `TARZAN_USE_METAL` selects the backend before PS2Recomp
configures. The Metal runtime does not fetch or link raylib/GLFW/rlImGui/ImGui; legacy
window, sample-audio and input fallback code stays in the non-Metal backend.
Metal input uses the native action IDs directly. The runner has no direct
OpenGL/Carbon imports; SDL entry points resolve from the GS bridge, whose
existing Carbon import remains outside this runner cleanup. The input smoke
uses that same linkage. Verify the runner with `nm` and `otool -L` after
`./tz build`.

## Roadmap

Ranked by expected value divided by effort and risk. Every item needs checking against our code, re-measuring on Tarzan, a kill-switch and a verify mode, and runs through the AGENTS.md loop.

### iOS / tvOS track

Feasible, and the ahead-of-time design is the key advantage: no JIT anywhere (no `mmap`/`PROT_EXEC`/`MAP_JIT`), and the VU and IOP fallbacks are interpreters. Landscape only; GitHub sideload distribution. It is a device-validation project, not a recompile. Blockers: memory (jetsam limits with upscaled GS textures) and the port work below.

Toolchain on macOS 11.2 (verified to the SDK level): Xcode 12.5.1 runs on macOS 11.0+ and carries the iPhoneOS/AppleTVOS 14.5 SDKs and the Metal 2.3 compiler. Expand the `.xip` with `xip -x` anywhere (no `/Applications` install), accept its license once (`sudo DEVELOPER_DIR=<Xcode.app>/Contents/Developer xcodebuild -license accept`; `metal -std=ios-metal2.3` then works), and point `DEVELOPER_DIR` at it. Native code is built by our LLVM 19 (`-target arm64-apple-ios14.0` / `arm64-apple-tvos14.0`, `-isysroot` the SDK, `ld64.lld`, which the bootstrap does not build yet); Xcode supplies `metal`/`metallib` (`-std=ios-metal2.3`) and `actool` (tvOS layered icons). Newer xcodes CLI releases need macOS 12; Apple ID downloads go through the browser.

Planned `tz package --platform ios|tvos --iso <disc> [--developer-dir PATH]` (no separate command): preflight (SDK, Metal tools, lld; exit 2 naming the missing piece), cross-build engine and dependencies per platform, compile shaders and assets, verify and import the user's disc into the bundle (same checks as `tz disc`), audit the bundle, zip `Payload/Tarzan.app` as an unsigned `.ipa`. The result contains game data: a personal build product, never committed or shared. Signing is the user's (Sideloadly/AltStore).

| Step | Work | Effort |
|---|---|---|
| 1 | Host-agnostic core (also simplifies macOS). Already true: one process (`host/launcher.cpp` calls `tarzan_run` in-process), settings in a struct (`host/settings.hpp`); the only `getenv("HOME")` is `defaultUserDirectory()`. PCSX2 Metal renderer on iOS (about 85% confidence for iOS, 60% for tvOS): ARMSX2 (GPL-3.0, `platforms/ios/`) ships it; upstream Metal code is iOS-aware. Our bridge needs no JIT (static AOT software rasterizer functions), so no `allow-jit`. Fixes in `deps/pcsx2` `pcsx2/GS/Renderers/Metal/*` and the bridge, using ARMSX2's diffs as the template:
- View: retain the caller's `CAMetalLayer` instead of an `NSView`; iOS surface kind in `metal_surface_adapter.mm` (S-M).
- Gate `setDisplaySyncEnabled` behind `#if !TARGET_OS_IPHONE`; `MTLCreateSystemDefaultDevice` instead of `MTLCopyAllDevices`; drop the `MTLFeatureSet_macOS` check; stub IOKit power assertions and CocoaTools.
- `texture_barrier = false` on iOS (Apple GPUs cannot order RT reads inside a pass); keep `framebuffer_fetch`. This is the one fix needing gameplay validation of blending and depth.
- BC textures from `supportsBCTextureCompression`; `m_use_present_drawable = Always`.
- Shaders: compile the same `.metal` sources (`xcrun -sdk iphoneos metal -std=ios-metal2.3 -target air64-apple-ios14.0` to `Metal23.metallib`, simulator equivalent) and ship them in the bundle. Upstream passes `-ffast-math` to the shader compiler; decide deliberately, it conflicts with our arithmetic rule (GPU side only).
- Build: PCSX2 has no iOS toolchain; use `CMAKE_SYSTEM_NAME=iOS`, `CMAKE_OSX_SYSROOT`, Vulkan/OpenGL/Qt/tests off, cross-build zstd, lz4, png, freetype (M-L).
- tvOS: same Metal surface, MetalFX disabled, cache-only storage, A10X or newer.

Prototype order (1-2 days each): compile the Metal GS files plus shaders for the simulator; simulator bridge with a `CAMetalLayer` harness; replay a captured GS dump; device build (free signing, no JIT) comparing pixels against macOS; a live Tarzan scene checking pacing and thermals; validate the barrier fallback on A14/A15/M1. Then a minimal iOS app with the bridge at 1x measuring memory, generated-code link under Xcode, sustained thermals on an A14-class device.

Touch HUD: a custom `UIView` overlay with GameController as the primary path (`GCVirtualController` is only a stopgap: no drag, resize or per-control opacity). Two sticks, D-pad, 4 face buttons, L1/L2/R1/R2, Start/Select, pause; L3/R3 only if the game reads them (check which buttons Tarzan uses; the right stick may be camera). Edit mode (drag, resize, per-control opacity, hide, snap, reset), haptics, auto-hide when a controller connects, safe-area anchoring. Layout: versioned JSON per device class in Application Support, e.g. `{"version":1,"device":"iphone","controls":[{"id":"cross","anchor":"br","x":-96,"y":-64,"scale":1.0,"opacity":0.7,"hidden":false}]}`.
