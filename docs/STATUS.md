1. **tvOS gameplay freeze (open).** On the Apple TV 4K the guest stops submitting frames after 3–20 s of play (`[gs-game] frames=0` for the rest of the run) while the GS worker keeps presenting at 59.94/s, `pipeline_compiles=0`, CD I/O stays fast, and audio drains into underruns. `PS2X_DUMP_STATE_AT=25 PS2X_DUMP_STATE_EVERY=8` shows the guest audio thread (prio 6, entry `0x37B0B0`, its loop calls `WaitSema` `0x4461A0`) `running` in every frozen dump, the main thread (prio 100) never scheduled after holding a finished `sifcmd` invocation, and queued SIF invocations growing (0→27). The EE pushes exactly one 192-byte `OpGsVsync` per VBlank once frozen, so no rendering work reaches the worker. The same build and route on an iPhone 11 run at 60 fps with thread 3 blocked on semaphore 14. `PS2X_VU1_WORKER=sync` freezes earlier (at match-intro) and `=0` (inline) survived one run and froze at the language screen in another, so no data-side mode is exempt and neither is a shader-compile stall. Next: a bounded control-flow recorder for the `0x37B0B0` loop (WaitSema id, whether the count was consumed or the wait blocked, and the branch that exits the lap), then the input that branch reads. Reproduce with `./rx device run --seconds 70 --env PS2X_DUMP_STATE_AT=25 --env PS2X_DUMP_STATE_EVERY=8` on the Apple TV. Device observations regenerate with `./rx device install --lean`, `./rx device push-data` and `./rx device run --seconds 150`.
